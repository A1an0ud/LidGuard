# ابدئي من هنا: تسليم LidGuard

هذه الحزمة جاهزة للتجربة والرفع كمستودع كود. لم يُرفع مستودع GitHub من داخلها، ولم يُثبت بعد تشغيل Raspberry Pi أو كاميرته لدى الفريق. العرض المرفق مسودة معبأة تحتاج الروابط والصور الفعلية ورمز الفريق وتحديث حالة الجهاز.

## الخطوة الأولى: شغلي البرنامج على Windows

1. حمّلي ملف الحزمة إلى اللابتوب وافكي الضغط كاملًا.
2. افتحي مجلد `LidGuard_Medathon_Prototype`.
3. اضغطي مرتين على `START_WINDOWS.bat`.
4. إذا ظهر أن Python غير موجود، ثبتي Python من الموقع الرسمي المذكور في الرسالة، ثم شغلي الملف مرة ثانية. لا يلزم تثبيت أدوات تدريب حتى يعمل العرض.
5. انتظري فتح المتصفح على `http://localhost:8765`. أبقي نافذة الأوامر مفتوحة.
6. جرّبي Simulation: Closed ثم Open ، وانتظري خمس ثوانٍ حتى يظهر التنبيه. هذا اختبار محاكاة معلن، وليس اختبار كشف من صورة.
7. اختاري Image test ، ثم صورة من مجموعة RGB الموجودة أصلًا عند الفريق. حددي عينًا واحدة، أكدي رؤيتها، واضغطي Classify selected eye.

إذا ظهر خطأ، صوّري نصه كاملًا. لا نحتاج تغيير البرنامج أو إعادة تثبيت النظام عشوائيًا.

## الخطوة الثانية: افصلي أدلة الاختبار

| الدليل | ماذا يثبت؟ | ماذا لا يثبت؟ |
|---|---|---|
| تغيير OPEN/CLOSED من Simulation | المؤقت والتنبيه والإقرار والسجل | دقة كشف العين من الكاميرا |
| تصنيف صورة من Image test | تشغيل النموذج على صورة جديدة للتطبيق | استمرار الفتح بمرور الوقت |
| صور كاميرا تتغير ويُحلل الجزء المحدد | تكامل مصدر الصور مع البرنامج | أداء سريري أو كشف قرنية مباشر |
| تشغيل Raspberry Pi و CSI فعليًا | تكامل الجهاز المصور | أن كل وظائف الفكرة اكتملت |
| نتائج holdout الموجودة | تجربة محددة على 21 صورة من شخصين خارج التدريب | أداء مرضى العناية أو NIR أو الكاميرا الحالية |

النتيجة العملية للبرنامج بعد شروط القبول: **18 صحيحة +1 خاطئة +2 غير محسومة** من 21 صورة. درجة التصنيف بين الصور التي صنفها 18/19. لا تكتبي «دقة الجهاز 95%».

## الخطوة الثالثة: GitHub

إذا لدى جوري مستودع قائم، ابدؤوا منه واحفظوا نسخة عملها قبل إضافة هذا المسار. لا تستبدلوا الملفات القديمة أو تاريخها دون مراجعة. هذه الحزمة تضيف مسار تشغيل مستقلًا، وتحتفظ بتقرير Orange السابق داخل reports.

إذا ما عندكم مستودع:

1. افتحي GitHub بالحساب الذي سيملك مشروع الفريق.
2. أنشئي مستودعًا باسم `LidGuard` أو `LidGuard-MEDATHON`.
3. اجعلي وصول المحكمين ممكنًا دون طلب إذن. المستودع العام Public هو أبسط طريقة عند اعتماد الفريق نشر هذه الملفات.
4. من صفحة المستودع اختاري رفع الملفات، ثم ارفعي **محتويات مجلد المشروع بعد فك الضغط**. يجب ظهور `README.md` و`app.py` ومجلدات الكود في الجذر. رفع ZIP فقط يصعّب استعراض الكود وتشغيله.
5. لا تضيفي أرشيفات الداتا أو `.venv` أوصور وجوه خاصة أو كلمات مرور. الحزمة الجاهزة لا تحتاجها.
6. احفظي التغيير برسالة واضحة مثل `Add runnable LidGuard engineering prototype`.
7. افتحي الرابط من نافذة خاصة، ثم جرّبي تنزيل ZIP من المستودع وتشغيله أو اجعلي عضوة ثانية تجربه.

المطلوب في العرض هو رابط صفحة المستودع، وليس رابط إعداداته أو رابط ملف محلي.

مساعدة GitHub الرسمية: https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository

## الخطوة الرابعة: الجهاز والتصوير

اتبعي [دليل الجهاز والتصوير](HARDWARE_AND_FILMING_AR.md). ابدئي بتشغيل النظام والكاميرا، ثم التطبيق. شاشة OLED ليست عائقًا للتسليم الأساسي.

لخيار Both ، تعليمات MEDATHON تطلب 6 صور: أمام/خلف/يمين/يسار/أعلى/أسفل، وفيديو تشغيل مدته 60–90 ثانية على Drive متاح دون طلب صلاحية، إضافة لرابط GitHub.

إذا لم يعمل الجهاز، اذكري ذلك وقدمي النموذج الرقمي التفاعلي وفق إعلان المنظمين. لا تُقدَّم صور قطع غير عاملة أو رندرات 3D باعتبارها صور جهاز متكامل يعمل. نوع التسليم في المنصة يجب أن يطابق ما أُنجز فعلًا؛ لا تختاري Both لمجرد امتلاك القطع.

## الخطوة الخامسة: أكملوا مسودة العرض

العرض باللغة الإنجليزية ويحافظ على أقسام القالب الرسمي. راجعوا قبل الرفع:

- رمز الفريق الحقيقي في اسم الملف.
- رابط GitHub ورابط Drive وفتح كل منهما من نافذة خاصة.
- الصور الفعلية والفيديو النهائي.
- هل الجهاز متكامل ويعمل؟ حدّثوا الحالة بعد اختباركم فقط.
- نتائج الاستبيان إن وصلت بالفعل، مع عدد المشاركين وطريقة جمعها. إذا لم تصل، لا تضيفوا نتيجة تقديرية.
- الأسماء والأدوار، والتكلفة الفعلية إن احتُسبت من الفواتير.
- حذف أي نص يطلب استكمال عنصر قبل التقديم.

اسم الملف حسب تعليمات القالب: `MED-رمزالفريق_LidGuard_Filter2`، مع استبدال الجزء التوضيحي برمزكم الحقيقي. لا ترفعوا المسودة باسم Working_Draft باعتبارها نهائية قبل سد هذه العناصر.
